\section{REST-Schnittstellen}
\textit{REST} ist die am meisten verbreitete Kommunikationsarchitektur zur Vernetzung von Maschinen und wird bei vielen Anwendungsfällen angewandt, wie z.B. \textit{IoT}-Technologien \cite{reinheimerIndustrieHerausforderungenKonzepte2017}. In diesem Zusammenhang werden zwei Entitäten unterschieden, nämlich der Server und der Client. Der Letzterer initialisiert die Anfrage, während der Server diese bearbeitet und je nach Fall eine Antwort zurückschickt. \cite{balzertLehrbuchSoftwaretechnikEntwurf2011}.

In REST werden Daten über HTTP übertragen und dadurch die Realisierung von Webservices ermöglicht. Jedes Objekt einer Anwendung repräsentiert eine Ressource auf die über eine Adresse (URI, eng:. \textit{Uniform Resource Identifier}) zugreifbar ist \cite{balzertLehrbuchSoftwaretechnikEntwurf2011}. Auf diese Ressource kann eine Anwendung zugreifen, wenn ihr der Identifikator, die zu auszuführende Aktion und das Format der erwartenden Antwort des Servers bekannt sind \cite{balzertLehrbuchSoftwaretechnikEntwurf2011}. Allgemein gilt, dass jede über \textit{HTTP} übertragene Botschaft alle Informationen enthalten darf, die für ihre volle Assimilierung auf Serverseite gebraucht werden, und daher wird die gleiche Anforderung von der REST-Schnittstelle geerbt.

In dieser Architektur werden vier HTTP-Methoden zur Verfügung gestellt: \textit{GET, PUT, POST und DELETE}. Diese werden jeweils verwendet, um das Aufrufen, das Hinzufügen, Verarbeiten und das Löschen von Daten im Server durchzuführen \cite{balzertLehrbuchSoftwaretechnikEntwurf2011}.
