\section{REST-Schnittstellen}
REST ist der am meisten verbreitete Kommunikationsarchitektur zur Vernetzung von Maschinen und wird bei mehreren Anwendungsfällen angewandt, wie z.B. IoT-Technologien \cite{reinheimerIndustrieHerausforderungenKonzepte2017}. In diesem Zusammenhang werden zwischen zwei Entitäten unterscheiden, nämlich der Server und der Client. Dieser initialisiert die Anfrage an den ersteren, der anschließend diese bearbeitet und dem Client zurückgibt \cite{balzertLehrbuchSoftwaretechnikEntwurf2011}.

In REST werden Daten über HTTP übertragen und wird es dadurch die Realisierung von Webservices ermöglicht. Ressourcen (jedes Objekt einer Anwendung) repräsentiert eine Ressource, die über eine Adresse (URI, eng:. \emph{Uniform Resource Identifier}) zugreifbar wird \cite{balzertLehrbuchSoftwaretechnikEntwurf2011}. Auf diese Ressource kann eine Anwendung zugreifen, wenn ihr den Identifikator, die zu auszuführende Aktion und das Format der erwartenden Antwort des Servers bekannt sind \cite{balzertLehrbuchSoftwaretechnikEntwurf2011}. Allgemein gilt, dass jede über HTTP übertragene Botschaft alle Informationen enthalten darf, die für ihr volle Assimilierung in der Serverseite gebraucht werden, und daher wird die gleiche Anforderung von der REST-Schnittstelle geerbt.

In dieser Architektur werden vier generische HTTP-Methoden zur Verfügung gestellt: GET, PUT, POST und DELETE. Diese werden jeweils verwendet, um das Aufrufen, das Hinzufügen, Verarbeiten und das Löschen von Daten des Servers auszuführen \cite{balzertLehrbuchSoftwaretechnikEntwurf2011}.
