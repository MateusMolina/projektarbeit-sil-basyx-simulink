Dieser Kapitel fängt mit einer Erläuterung davon an, was für Werkzeuge für die Entwicklung des Systems angewendet worden sind. Anschiließend wird es auf die Einkapsulung von BaSyx in einer S-Function und jede im System implementierte Fähigkeit eingegegangen, wobei jeweils das Konzept und Lösungsansatz kurz erklärt wird. Zum letzen Thema ist einen Überblick über den Entwurf direkt in der Simulationsumgebung vom Simulink gegeben, mit dem Schwerpunkt auf die Personalisierung der Benutzerschittstelle eines mit S-Function erstellten Blockes.

\subsection{Entwicklungsumgebung}

% [X] C++, CMAKE
Die Bibliothek wurde in C++ mit Visual Studio Code als integrierte Entwicklungsumgebung entwickelt. Zusätzlich war CMake durchaus eingesetzt, um das \textit{Packaging} der sämtlichen Modulen durchzuführen.

% [X] Testbasierte Entwicklung

Für alle Modulen wurde testgetriebene Entwicklung eingesetzt, um sicherzustellen, dass alle funktionelle  und nicht-funktionelle Anforderungen abgedecket werden. Darüber hinaus wurden beide \textit{google-test} und \textit{google-mock }für die Realisierung von Testfällen angewendet.

% [X] Docker

Für die Ausführung der Testszenerien sind eine Kombination aus Docker und Simulink verwendet worden, wobei die von BaSyx veröffentlichen Docker-Containers für den Registry- und AAS-Server für die Bereistellung der BaSyx-Architektur eingesetzt wurden.  

\subsection{Wrappen des BaSyx als S-Function}

% [X] Funktionweise des BasyxConnectors und wie es mit dem Block verbunden ist

Der \textit{BasyxConnector} wird innerhalb eines Blockes direkt aufgerufen, um Operationen wie einen AAS aus dem Registry-Server abzurufen und den Wert eines \textit{SubmodelElements} anzufragen, bzw. aktualisieren.

Ein Öffner der Klasse \textit{aasServerConnector} zeigt auf, dass diese im Konstruktor beide ein Objekt des Typs \textit{AAS} und \textit{HttpConnection} erfordert. Zum Aufbau eines AAS-Objekts wird es auf die Datei \textit{components.hpp} verwiesen, wobei eine neue Instanz entweder aus der Klasse \textit{registryServerConnector} über die Methode \textit{fetchAAS(...)} ausgegeben werden kann, oder anhand des ID und URL-Pfades erstellt werden kann. 

Ein \textit{HttpConnection}-Objekt kann über eine der Konstruktion einer der Implementierungen der Schnittstelle \textit{httpConnection.hpp} angelegt werden. Diese dient zu dem Tätigen von HTTP-Anfragen, wodurch eine effektive Entkopplung von deren  Ausführung und dem \textit{BasyxConnector} erreicht wird. Momentan wurde nur eine Implementierung (\textit{curlHttpConnection}) über die externe Bibliothek \textit{libcurl} realisiert.

Innerhalb der Datei \textit{PropertySAConnectorBlock.cpp} findet sich die Logik, um eine Verbindung mit beiden \textit{BaSyx} und \textit{Simulink} herzustellen. Die Klasse \textit{CurlHttpConnection} wird als Zeiger instanziiert, und als Argument zur Erstellung von Objekten des Paketes \textit{BasyxConnector} über die Methoden \textit{mdlStart und mdlOutputs} verwendet.

Mit diesen lässt sich Zustand innerhalb einer Block-Instanz speichern und dadurch Initialisierungsparameter wie \textit{aasId, registryUrl, submodelElementId} unter anderen beibehalten werden.

\subsection{A4: Anzeigen von Simulink-konformen Fehlermeldungen} \label{ProzessA4}

Wäre ein Status-Code nicht gleich 200 erhalten, löst der BasyxConnector eine Ausnahme mit Details des empfangenen Paketes aus, die weiterhin an dem entsprechenden Block zugeleitet wird. Für das Wrappen der Ausnahme wird eine Simulink-konforme Methode angewandt, durch die Fehldermeldungen direkt im Simulink-Console angezeigt werden können. Das Abbild \ref{fig:consolefehler} stellt eine beispiele Fehlermeldung, bei der der Server nicht in der Lage war, mit dem RegistryServer eine Verbindung herzustellen.

\subsection{A5: Anwendung von mehreren Blöcken in demselben Simulink-Modell}


% [X] Was passiert wenn mehrere Block im gleichen Modell eingeführt werden? (seitens Matlab)
Aus Sicht Matlab/Simulink ist ein mit S-Functions entwickelter Block eine geteilte Bibliothek. Eine globale Variable ist deshalb mit allen anderen Blöcken gleiches Typs geteilt, was ein Problem für die Beibehaltung der Daten unter Simulationsschritten darstellt. Wie bereits erwähnt, können zur Umgehung dieses Problems und um den Blöcken einen internen Zustand zu verleihen, \textit{work}-Vektoren verwendet werden.

\subsection{A7: Personalisierung der Blockbenutzeroberfläche} \label{Simulationsumgebung}

Wie im Kapitel \ref{BenutzeroberflaecheSimulink} kurz erläutert, bietet Simulink mehrere Möglichkeiten der Benutzeroberfläche eines Blockes zu personalisieren. 

Bei beiden Blöcken war es eine kritische Anforderung, dass alle einzustellenden Parameter gut erkennbar waren, um schnell von mehrfachen eingefügten Blöcken zu unterscheiden.

% [X] Bilder von Blöckenbenutzeroberflächen
% [X] Beschreibung der Bilder
Das Block-Symbol wurde personalisiert, um schnell einen Überblick der eingestellten Parameter zu bekommen. Dazu sind Informationen wie die Abtastrate und das verbundene \textit{SubmodelElement} und desses \textit{Submodel}, bzw. \textit{AAS} immer sichtbar, wie im Bild \ref{fig:sesab_block} dargestellt ist. Das ermöglicht die schnelle Erkennung und Unterscheidung von mehrfach eingefügten Blöcken in einem Modell.

\begin{figure}[H]\centering
    \includegraphics[width=15cm,keepaspectratio]{media/SeSAB_block.jpg}
    \caption{Instanz eines PropertySAConnector-Block}
    \label{fig:sesab_block}
\end{figure}

Nach Tippen auf einen Block wird dem Benutzer ein Dialogfenster mit Textfelder für alle einzustellende Parameter angezeigt. Das wurde erst durch die Erstellung einer Maske für die S-Function, eine im Simulink eingebettete Funktionalität. Das Abbild \ref{fig:sesab_dialog} zeigt ein Beispiel einer Instanz des Blockes \textit{PropertySAConnectorBlock}.

\begin{figure}[H]\centering
    \includegraphics[width=15cm,keepaspectratio]{media/SeSAB_dialog.jpg}
    \caption{Dialogfenster des PropertySAConnector-Block}
    \label{fig:sesab_dialog}
\end{figure}

Der Benutzer kann über das Fenster den gewünschten Betriebsmodus auswählen, wobei bei Wählen des Echtzeit-Modus das Feld zur Einstellung der Abtastrate sichtbar wird. Es steht außerdem zur Verfügung die Möglichkeit, auszuwählen, ob es das \textit{AAS} über den \textit{RegistryServer} oder direkt über seine Adresse abgerufen werden soll.
